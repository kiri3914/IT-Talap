# Черновик письма в hh

**Кому:** команде API hh. Адрес уточнить на dev.hh.ru — в условиях API указан
порядок обращения по вопросам доступа (п. 3.9). Копию — ТОО «HEADHUNTER.KZ»,
раз основная страна проекта — Казахстан.
**Зачем:** условия API разрешают использовать данные для «получения информации
о рынке труда» (п. 3.3), но запрещают формировать другую базу и давать к ней
доступ (п. 4.3), передавать данные третьим лицам (п. 4.6) и требуют удалять
вакансии, ушедшие в архив (п. 3.11). Подробно — [hh.md](hh.md) §5.

**Отправляет:** Бектур. Я письма не отправляю.

**Когда:** когда команда посмотрит внутреннюю версию и согласится с тем, что
просим. Письмо с конкретными вопросами и готовым продуктом получает конкретный
ответ; письмо «можно ли нам всё» — отказ или молчание.

---

## Что приложить

- 3–4 скриншота внутренней версии: обзор рынка, страница профессии, рентген
  вакансии. Без названий компаний-физлиц.
- Ссылку на репозиторий: код и методология открыты.
- Ссылку на методологию (страница «Методология» или docs/).

## Текст

**Тема:** Талап — исследовательский проект о рынке IT-труда Центральной Азии на API hh: просим согласовать публикацию

Здравствуйте!

Меня зовут Бектур Токтогулов, я дата-инженер из Казахстана. С командой из
пяти человек мы делаем Талап — открытый некоммерческий проект об IT-рынке труда
Казахстана, Узбекистана и Кыргызстана. Код и методология открыты:
https://github.com/kiri3914/IT-Talap

**Что мы делаем.** С 11 сентября 2026 года раз в сутки собираем IT-вакансии
через официальный API hh с токеном приложения — 25 профессий IT-категории,
hh.kz, hh.uz и hh.kg, около 3 300 вакансий в день, с соблюдением лимитов.
Из ежедневных снимков считаем то, чего нет в срезе на сегодня: как меняется
спрос, сколько вакансий указывают зарплату, сколько живёт вакансия, где
нанимать труднее всего.

**Что уже сделано.** Внутренняя версия сайта, которую видит только команда.
Ничего не опубликовано: прежде чем публиковать, мы хотим согласовать это с вами.

**Что мы хотели бы публиковать — и что именно спрашиваем.**

1. *Агрегаты рынка*: медианы зарплат по профессиям, опыту и городам, доля
   вакансий с зарплатой, динамика спроса, срок жизни вакансий. Мы понимаем это
   как «получение информации о рынке труда» по п. 3.3. Верно ли наше понимание?

2. *Страницу отдельной вакансии*: когда вакансия появилась, сколько раз её
   поднимали в поиске и меняли вилку, и сколько предлагают похожие вакансии,
   если зарплата не указана. Без текста вакансии — со ссылкой на оригинал на
   hh, откуда человек и откликается. Допустимо ли это с учётом пп. 4.3 и 4.6?

3. *Историю закрытых вакансий*. Для статистики срока жизни нам нужно хранить
   вакансии после того, как они ушли в архив. Публично мы готовы показывать
   закрытые вакансии только в агрегатах — без страниц отдельных вакансий.
   Устроит ли это вас с учётом п. 3.11?

4. *Страницы компаний*: сколько вакансий открывает компания, в каких ролях,
   указывает ли зарплату. Только юрлица — работодателей-физлиц мы не
   показываем.

**Что мы обещаем в любом случае.**

- Ссылка на hh у каждой цифры и каждой вакансии, указание источника.
- Никаких текстов вакансий и контактов — только извлечённые поля.
- Некоммерческое использование. Если когда-нибудь появится платная часть —
  только после отдельного согласования с вами.
- Удаление по первому запросу: вакансии, компании или всего, что вы попросите.
- Сбор только через официальный API, в пределах лимитов.
- Если вашей исследовательской команде пригодятся наши агрегаты по региону —
  отдадим.

Если какая-то часть невозможна — подскажите, в каком виде она была бы
допустима. Будем благодарны за ответ.
