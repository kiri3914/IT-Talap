## 1. Вердикт

**Рекомендация:** брать в Фазу 1 — P0

**Обоснование:** официальный REST API, покрывает все три страны, справочники открыты.
**Блокер:** поиск вакансий закрыт для анонимных запросов — нужен токен приложения.

---

## 2. Способ доступа — проверено

Один API `api.hh.ru` на все страны. hh.kz / hh.uz / hh.kg — не отдельные API,
различаются параметрами `area` и `host`. Подтверждено.

### Открыто без авторизации

| Эндпоинт | Статус |
|---|---|
| `GET /areas` | 200 ✅ |
| `GET /professional_roles` | 200 ✅ |

### Требует авторизации

| Эндпоинт | Статус |
|---|---|
| `GET /vacancies` | **403 forbidden** ❌ |

Проверено 2026-09-04 с тремя вариантами заголовков:

```
[осмысленный UA]  403 {"errors":[{"type":"forbidden"}]}
[браузерный UA]   403 {"errors":[{"type":"forbidden"}]}
[без UA]          403 {"errors":[{"type":"forbidden"}]}
```

**Вывод: дело не в User-Agent.** Анонимный доступ к поиску вакансий закрыт.
Требуется регистрация приложения и токен.

Регистрация: https://dev.hh.ru/admin — создать приложение, получить credentials.

## 4. Ограничения — НЕ проверено

Проверить сразу после получения токена, до того как закладываться в коде:

- [ ] Реальная граница глубины выдачи (`page * per_page`; в документации 2000)
- [ ] Rate limit: заявленный и наблюдаемый
- [ ] `found` по каждой из 25 IT-ролей на страну — сколько срезов упирается в лимит
- [ ] Есть ли полное описание в списке или только в `/vacancies/{id}`
- [ ] Работают ли `date_from` / `date_to` для нарезки окон
- [ ] Отдаёт ли API признак архивной/закрытой вакансии

Текущий код исходит из документированного лимита 2000 — константа `DEPTH_LIMIT`
в `ingestion/sources/hh.py`. Поправить по факту замера.
