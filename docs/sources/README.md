# Задача #1 — Разведка источников данных

**Тип:** исследование, параллельная работа
**Срок:** 5 дней
**Результат:** по файлу на источник в `docs/sources/` + сводная таблица в этом файле

---

## Зачем

Прежде чем писать парсеры, нужно знать, откуда вообще можно собирать и с какими ограничениями. Плохо выбранный источник — это неделя работы в мусор.

Вторая цель — правовая. По ТЗ (§3.3) ни один источник не подключается без зафиксированной проверки `robots.txt` и ToS. Эта задача её закрывает.

---

## Как делать

1. Взять источник из списка ниже (записать своё имя рядом, чтобы не дублировать)
2. Скопировать `_TEMPLATE.md` в `<source>.md`
3. Заполнить **проверенным**, а не предположениями
4. PR в отдельной ветке `source/<name>`

**Главное правило: всё, что не проверено руками, помечается как непроверенное.** Строка «лимит 2000» без выполненного запроса — это не факт, а слух. Один непроверенный факт в этом документе стоит недели работы позже.

Минимум, который надо реально сделать по каждому источнику:

- открыть `robots.txt` и прочитать
- найти и прочитать ToS в части автоматического сбора
- выполнить хотя бы один настоящий запрос и приложить кусок ответа
- посмотреть глазами 30–50 вакансий и оценить долю с указанной зарплатой

## Что делать со «сложными» находками

Если попался источник с капчей, обязательной авторизацией или запретом в ToS — **не пытаться обойти**. Записать в файл как «не берём» с причиной. Это полноценный результат задачи, а не неудача.

## Выводы разведки

**1. Ограничитель — правовой, а не технический.** Три площадки отпали по ToS, причём две из них (getmatch, hirify) были технически удобны. У hirify запрет описывает наш случай дословно, включая «независимо от способа сбора». Это снимает вопрос «а может, всё-таки».

**2. Узбекистан — дыра.** Лучший локальный источник (ishkop.uz, 676 вакансий, 65% с вилками) закрыт запретом в ToS. Остаются hh.uz и @uzdev_jobs. Покрытие по стране будет заметно слабее, чем по Казахстану, — это надо будет сказать в методологии, а не прятать.

**3. Публичного API нет ни у кого, кроме hh.** Каждый следующий источник — это парсер со своей поддержкой. Довод против гонки за количеством: лучше вычерпать hh + 2-3 хороших, чем держать десять хрупких.

**4. Телеграм ценнее, чем ожидалось.** Вилки почти в 100% постов против ~50% на hh, ссылок на hh нет — вакансии частично уникальные. Но стабильного ID нет (только `channel + message_id`), поэтому репост = новая «вакансия», а закрытие не отражается никак. Времени жизни вакансии телеграм не даст.

**5. Дубли между источниками — риск, который вылез дважды.** @headhunter_uz ретранслирует hh.uz; enbek.kz по собственному описанию агрегирует другие площадки. Оба задвоили бы спрос. Вывод: замер пересечения обязателен до загрузки в общую базу, а дедупликация нужна раньше, чем стояла в плане Фазы 2.

**6. Хабр Карьера выбывает из P2.** В ТЗ v1 и v2 он числился приоритетным источником — на предположении. Проверка: по Ташкенту 0 вакансий, всего на сайте 1253. Регион не покрыт.

## Дефекты данных, найденные заранее

**hirehi.ru** — два, оба серьёзные:
- зарплата **всегда в RUB**, включая Алматы, Ташкент и Бишкек; тенге на страницах нет вообще. Исходная сумма и курс пересчёта потеряны безвозвратно
- `addressCountry: "RU"` у всех проверенных алматинских вакансий — поле страны сломано, страну надо выводить из города

Плюс это не вилка, а одна граница («от 22 793 ₽»), и заполнена она у 25% карточек; в остальных строка-заглушка `"зпнеуказана"` в числовом поле.

Хорошая новость: такие вещи обычно находят на третьей неделе разбора данных, а не до написания парсера.
