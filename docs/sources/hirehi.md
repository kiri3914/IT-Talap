| Нужна регистрация приложения / токен? | Для публичных страниц — нет |
| Документация API (URL) | не найдена |
| Работает ли без авторизации | **Да.** Обычный `curl` с обычным User-Agent, HTTP 200, без капчи, без cookie, без JS. Все нужные данные в HTML |

## 5. Правовая проверка — обязательно

| Вопрос | Ответ | Цитата / ссылка |
|---|---|---|
| `robots.txt` — что запрещает | `/admin/*`, `/static/admin/`, `/upload_company_logo`, `/admin/login`, `/admin/logout`, **`/api/`**, `/*?*search=`, `/*?*sort=`. Одинаковые правила для 4 групп агентов, включая явно названные `Scrapy`, `GPTBot`, `CCBot`, `anthropic-ai`, `Claude-User`, `Claude-SearchBot`. Страницы вакансий, городов и `?page=` **не запрещены** | https://hirehi.ru/robots.txt |
| ToS: запрещён ли автоматический сбор | Да, но **условно** — запрет сформулирован как «без разрешения», то есть допускает получение разрешения | п. 12 https://hirehi.ru/usloviya (редакция от 2 августа 2026) |
| ToS: разрешено ли некоммерческое использование | Отдельной оговорки про некоммерческое использование нет | там же |
| ToS: разрешена ли публикация производных данных | Прямо не урегулировано. П. 15 закрепляет права на «программный код, дизайн, структуру сайта, обозначения и материалы HireHi» за ИП Захаровым А. А. | п. 15 |
| Есть ли отдельные условия для API | Нет. Оферта (`/oferta`) регулирует только платные функции, про сбор данных в ней ничего нет |

**Дословная цитата ключевого пункта ToS (п. 12 «Запрещённые действия»):**

> 12. Запрещённые действия
> нарушать закон, права третьих лиц или условия обработки персональных данных; создавать фиктивные аккаунты, выдавать себя за другое лицо или компанию; публиковать фальшивые вакансии, мошеннические предложения и скрытую рекламу; **массово копировать, индексировать, выгружать или продавать данные без разрешения**; обходить лимиты, оплату, авторизацию или технические ограничения; загружать вредоносный код, пытаться получить несанкционированный доступ или мешать работе сайта; передавать специальные категории данных и данные третьих лиц без законного основания; использовать автоматический результат как единственное основание для дискриминационного решения.

*(выделение моё — ключевая формулировка «без разрешения»)*

Существенная оговорка из п. 1 тех же условий:

> Просмотр открытых страниц без аккаунта не создаёт договорных отношений сверх правил, применимых к посетителю.

**Вывод:** нужно уточнение

Почему не «нельзя» и не «можно». В отличие от getmatch и Hirify, здесь запрет не абсолютный: формула «без разрешения» прямо предполагает, что с разрешением — можно. Плюс п. 1 говорит, что просмотр открытых страниц без аккаунта не создаёт договорных отношений — то есть аргумент, что ToS вообще не связывает анонимного посетителя, небезоснователен. **Но опираться на это толкование я не рекомендую**: п. 12 сформулирован как правило поведения, а не как условие аккаунта, а объём сбора для Talap — именно «массовый». Правильный путь — письменный запрос.

**Практический следующий шаг:** написать владельцу и получить письменное разрешение. Контакт указан в п. 7 самих условий: **anton_zakharov@hirehi.ru** (площадка принадлежит ИП Захарову Антону Алексеевичу, п. 15). В запросе имеет смысл сослаться на некоммерческий аналитический характер Talap, назвать планируемую частоту обращений и предложить обратную ссылку на оригинал вакансии.

## 6. Качество данных

Проверено на 28 карточках вакансий Алматы. **Все 18 полей JSON-LD присутствуют во всех 28 карточках** — схема стабильная, без пропусков.

- [x] Стабильный ID вакансии — числовой суффикс URL (`/development/ai-engineer-76593` → `76593`), плюс отдельное поле `identifier` в JSON-LD
- [x] Дата публикации — `datePosted`, ISO 8601. Есть и `validThrough` (везде ровно +90 дней от `datePosted`)
- [x] Название компании — `hiringOrganization.name`. Реальные KZ-работодатели: Kaspi.kz, Halyk Bank, Kolesa Group, Tele2 Kazakhstan, Freedom Афиша, Astana Hub. Часть скрыта под `NDA` (5 из 28)
- [~] Зарплатная вилка — **не вилка**. Всегда одно число (`value`), полей `minValue`/`maxValue` нет; на странице отображается как «от 22 793 ₽» или «до 190 793 ₽» — то есть односторонняя граница. Заполнено у 25 %, у остальных строка-заглушка `"зпнеуказана"` в числовом поле
- [~] Валюта — поле есть, но **всегда `RUB`**, в том числе для Алматы, Ташкента и Бишкека. Исходная валюта (KZT/UZS/KGS) не сохраняется, курс и дата пересчёта неизвестны
- [ ] Указание gross/net — отдельного поля нет; в просмотренных карточках в тексте тоже не встретилось
- [x] Город — `jobLocation.address.addressLocality` («Алматы»). **Но `addressCountry` неверный: `"RU"` для всех 28 алматинских вакансий.** Страну надо выводить из города/URL, полю доверять нельзя
- [x] Формат работы — `employmentType` (`FULL_TIME`) + `workHours`; офис/удалёнка есть в тексте и в meta description («Работа в офисе Алматы»)
- [x] Грейд явно указан — в `<meta name="description">` в скобках: «...для образовательного проекта **(middle)** в компании ITCBootcamp». Отдельным полем в JSON-LD нет, но парсится надёжно. Есть и грейдовые лендинги
- [x] Скиллы отдельным полем — **да**, поле `skills`, значения через `;`. Правда, это скорее нарезанные требования, чем нормализованные теги: «Более 5 лет коммерческой разработки на Java;Знание Java 17+ ...». Плюс отдельные `experienceRequirements` и `qualifications`
- [x] Полное описание — `description`, структурированный текст с секциями «Описание / Задачи / Требования / Условия»
- [ ] Признак «вакансия закрыта/архив» — не проверено. Косвенный кандидат — `validThrough`, но это плановая дата, а не факт закрытия

**Есть ли стабильный `source_id`:** да — числовой ID из хвоста URL, дублируется в поле `identifier`

**Пересечение с hh (на глаз):** не измерял. Условия использования, п. 7, прямо признают агрегацию: «Вакансии могут поступать от работодателей, из открытых источников или обрабатываться автоматически для отображения». Работодатели в выборке (Kaspi.kz, Halyk Bank, Kolesa Group) — крупные, они же активно публикуются на hh.kz, так что пересечение, скорее всего, заметное. Нужна дедупликация по паре «компания + название», ID у источников разные.

Там же, в п. 7, площадка сама снимает с себя гарантии по качеству: «HireHi не гарантирует постоянную актуальность каждой вакансии, ссылки, зарплаты, контакта или описания».

## 7. Оценка трудозатрат

| Параметр | Оценка |
|---|---|
| Сложность подключения | **низкая.** Sitemap отдаёт все URL, JSON-LD снимает парсинг HTML, пагинация тривиальная, авторизация не нужна, антибота нет |
| Время на реализацию | ~4-6 часов на рабочий коннектор (обход sitemap → карточки → парсинг JSON-LD → нормализация). Отдельно нужна работа по валюте: пересчёт RUB обратно в KZT осмысленно не восстановить, так что либо хранить как RUB с пометкой «пересчитано источником», либо не брать зарплату с этого источника вовсе |
| Риск поломки при изменениях на стороне источника | **низкий.** JSON-LD `schema.org` — стандарт, площадке невыгодно его ломать (это SEO). Риск скорее в смене URL-схемы категорий |

## 8. Что осталось непроверенным

- **Разрешение от владельца не запрошено** — это блокирующий пункт, письмо на anton_zakharov@hirehi.ru не отправлялось.
- Доля активных vs архивных среди ~20 630 URL в сайтмапах.

- Признак закрытой/архивной вакансии — есть ли он вообще.
- Наличие фильтра по дате публикации.
- Внутренний API (`/api/`) намеренно не зондировался — закрыт в robots.txt.
- Указание gross/net — не нашёл, но проверил только 28 карточек одного города.
- Есть ли где-то на сайте исходная сумма в тенге (в тексте описания, в кабинете) — проверял только JSON-LD, meta и карточку выдачи.
- Долю с зарплатой считал только по Алматы; по Ташкенту и Бишкеку не проверял, там может отличаться.
- Rate limit при объёмах, близких к полному обходу (~20 тыс. запросов) — проверено только ~50.
