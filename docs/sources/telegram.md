## 3. Способ доступа

**Тип:** Telegram (веб-превью + MTProto-клиент)

| Вопрос | Ответ |
|---|---|
| Есть публичный API? | Да, MTProto (Telethon/TDLib). Bot API для чтения чужих каналов не годится — бот должен быть админом канала. |
| Нужна регистрация приложения / токен? | Да: `api_id` + `api_hash` на https://my.telegram.org + номер телефона для авторизации user-сессии. Аккаунт-«читатель» = живой номер. |
| Документация API (URL) | https://core.telegram.org/api, https://docs.telethon.dev |
| Работает ли без авторизации | Частично: `https://t.me/s/<channel>` отдаёт HTML-ленту публичного канала без логина — этим и собраны данные выше. Пагинация назад через `?before=<msg_id>`. Для полной истории и надёжности нужен MTProto. |
| Есть ли пагинация и её лимиты | HTML: `?before=<id>`, ~20 постов на страницу, глубина ограничений в лоб не тестировалась. MTProto `GetHistoryRequest`: до 100 сообщений за запрос, вся история доступна. |
| Есть ли полное описание вакансии в списке | Да — пост и есть вакансия целиком, отдельный запрос не нужен. Длинные посты в HTML-превью могут быть обрезаны — не проверено. |
| Есть ли фильтр по дате публикации | В MTProto — `offset_date`. В HTML — только перемотка по `before`. |
| Есть ли фильтр по профессии/категории | Нет. Только хэштеги, и только там, где канал их ставит (@findwork, @uzdev_jobs). |

**Пример запроса, который реально отработал:**

```
GET https://t.me/s/workitkz
GET https://t.me/s/devkz_jobs
GET https://t.me/s/findwork
```
(HTML-лента, без авторизации, 2026-09-04)

**Пример ответа (обрезанный):**

```
Полный HTML со списком постов; в каждом <div class="tgme_widget_message"
data-post="workitkz/<msg_id>"> — текст поста, время, реакции.
Сырой JSON здесь неприменим: превью отдаёт HTML, а не API-ответ.
Пример ответа MTProto не приводится — Telethon в этой разведке не запускался.
```

## 4. Ограничения

| Ограничение | Значение |
|---|---|
| Rate limit (заявленный) | Официальных цифр для MTProto нет; сервер отвечает `FLOOD_WAIT_X` — клиент обязан ждать X секунд. Для HTML-превью лимиты не документированы. |
| Rate limit (наблюдаемый) | При ~12 запросах к t.me/s/ подряд ничего не сработало. Долгая пагинация не проверена. |
| Лимит глубины выдачи | MTProto — вся история канала. HTML — не проверено. |
| Капча / антибот | В превью не встретилась. Для MTProto — SMS-код при логине; риск «подозрительной активности» на новом аккаунте реален. |
| Блокировка по IP замечена | Нет (за время проверки). Отдельный риск: аккаунт может быть ограничен/забанен за поведение бота — не проверено. |

## 6. Качество данных

Что есть в вакансии на этой площадке:

- [ ] Стабильный ID вакансии — **нет**; есть только ID сообщения
- [x] Дата публикации — время поста (но это дата поста, а не дата вакансии; репост той же вакансии даёт новую дату)
- [x] Название компании — почти всегда в тексте, отдельным полем нет
- [x] Зарплатная вилка — в тексте, но в профильных каналах почти всегда
- [x] Валюта — ₸ / сум / сом / $ вперемешку, в тексте
- [ ] Указание gross/net — редко и непоследовательно (у @headhunter_uz есть, т.к. это карточка hh)
- [x] Город — в тексте или хэштеге (#bishkek у @findwork)
- [x] Формат работы — обычно указан словом (офис/удалёнка/гибрид)
- [ ] Грейд явно указан — только в заголовке должности (Junior/Middle/Senior), отдельного поля нет
- [ ] Скиллы отдельным полем — нет, только внутри текста (хэштеги у @uzdev_jobs/@findwork — частично)
- [x] Полное описание — да, весь пост
- [ ] Признак «вакансия закрыта/архив» — **нет**. Пост живёт вечно; закрытие вакансии никак не отражается. Иногда правится текст (edit) — это ловится по `edit_date`.

**Есть ли стабильный `source_id`:** нет в смысле «ID вакансии». Технически стабильна пара `(channel_username, message_id)` → канонический URL `t.me/<channel>/<id>`. Её и надо брать как `source_id`, помня, что одна вакансия может иметь несколько таких ID.

**Пересечение с hh (на глаз):** низкое у профильных IT-каналов (@workitkz, @devkz_jobs, @uzdev_jobs, @findwork — ссылок на hh не замечено вообще, отклик идёт в личку рекрутеру в Telegram) и **полное у @headhunter_uz**, который прямо ретранслирует карточки hh.uz — его брать как источник смысла нет, он дублирует hh-коннектор. Отдельное пересечение: @findwork дублирует собственный сайт devkg.com — вакансии там же с ID `devkg.com/tg/j-<ID>`, и **разумнее парсить devkg.com, а не канал**, там ID стабильный.

## 8. ГЛАВНАЯ ПРОБЛЕМА: нет ID и нет структуры

Это ключевое отличие Telegram от hh, и оно определяет всё остальное.

**1. Нет ID вакансии.** Единственный стабильный ключ — `(channel, message_id)`, то есть идентификатор *сообщения*, а не *вакансии*. Следствия:
- одна вакансия, запощенная в трёх каналах, — это три разных `source_id`;
- репост той же вакансии через две недели (обычная практика — «поднять» объявление) — ещё один ID и новая дата публикации, из-за чего поток «новых вакансий в день» завышается;
- удалённое сообщение просто исчезает, и это не значит, что вакансию закрыли.

**2. Нет схемы.** Даже в самых аккуратных каналах шаблон — это соглашение админа, а не формат. Спектр по нашим каналам:
- **@findwork** — почти машиночитаемо: фиксированные поля, вилка, хэштег города, ссылка с ID. Парсится регулярками с хорошей точностью;
- **@workitkz, @devkz_jobs, @uzdev_jobs** — устойчивый, но «человеческий» шаблон: подписи полей плавают, эмодзи вместо ключей, порядок меняется. Регулярки дадут заметный процент промахов;
- **@vacancykgg** — свободный текст, регулярками не берётся.

**3. Что конкретно сложно извлечь:**
- **зарплата** — форматов много: «450 000–1 400 000 ₸», «до 1 000 000 ₸», «от $2000», «10–12 млн сум», «база 300К + KPI». Нужен нормализатор с валютой, периодом, признаком «до/от» и отсечением бонусной части, плюс курс на дату поста для сравнимости между ₸/сум/сом/$;
- **грейд** — только из заголовка, а заголовки пишут как попало;
- **стек** — только NER/словарь по тексту;
- **gross/net** — чаще всего просто отсутствует, и восстановить неоткуда.

**4. Дедупликация.** Точного ключа нет ни внутри Telegram, ни против hh. Реалистичный путь — только вероятностный: нормализованное `(компания + должность + город)` как блокирующий ключ, поверх него нечёткое сравнение текста (шинглы/MinHash или эмбеддинги) с порогом, и обязательное окно по времени. Осложняется тем, что компанию часто не пишут вовсе («крупный финтех», «продуктовая команда»), а отклик идёт в анонимную личку — то есть у части постов нет ни одного надёжного идентифицирующего поля.

**Практический вывод.** Telegram не даёт «строк в таблице» — он даёт текстовый поток, из которого поля надо извлекать вероятностно. Для метрик по зарплатам он ценен именно тем, что вилку указывают почти всегда. Правильная стратегия: начать с 3–4 самых структурированных каналов (**@findwork — а лучше сразу devkg.com, @workitkz, @devkz_jobs, @uzdev_jobs**), считать источник «вторым мнением» к hh, помечать все извлечённые поля флагом низкой достоверности и никогда не смешивать с hh в одной таблице без явного признака источника.

## Технический доступ — ПРОВЕРЕНО 2026-09-12, Telethon НЕ нужен

Главный вывод разведки пересмотрен: **api_id, api_hash и номер телефона
не требуются.** У публичных каналов есть веб-превью `t.me/s/<канал>`,
которое отдаётся обычным HTTP без авторизации.

```
GET https://t.me/s/workitkz            → 200, ~160 КБ HTML, 20 постов
GET https://t.me/s/workitkz?before=N   → следующие 20 постов
GET https://t.me/robots.txt            → 404 (robots.txt отсутствует)
```

Из каждого поста вытаскиваются:

| Поле | Источник в HTML |
|---|---|
| `post_id` | `data-post="channel/12345"` |
| `message_id` | числовая часть post_id |
| `published_at` | `<time datetime="2026-09-11T05:29:01+00:00">` — ISO с таймзоной |
| `views` | `tgme_widget_message_views` — «10.3K», парсится в 10300 |
| `text` | полный текст поста |
| `hashtags` | извлекаются из текста |

Реализация: `ingestion/sources/telegram.py`, запуск `python -m ingestion.run_telegram`.
Пауза между запросами 1 с — это веб-морда, а не API для машин.

### Просмотры — неожиданная находка

Счётчик просмотров есть у 100% постов. Это **не отклики**, но единственный
доступный сигнал интереса к вакансии во всём проекте: ни hh, ни другие

## Правовое — НЕ ЗАКРЫТО

- `t.me/robots.txt` → **404**, файла нет: ни разрешения, ни запрета
- Условия использования Telegram дословно **не прочитаны** — блокер
- Веб-превью `t.me/s/` — публичная страница, предназначенная для шаринга
  и индексации поисковиками, но это наше рассуждение, а не пункт ToS
- Авторские права на тексты постов принадлежат авторам

**Подход по ТЗ §10:** храним агрегаты и ссылку `t.me/<channel>/<id>`,
полные тексты чужих объявлений не публикуем. Это снимает основной риск
по авторскому праву, но не заменяет чтение ToS.

**Прежде чем ставить сбор на расписание — прочитать Terms of Service Telegram
и записать сюда дословную цитату про автоматический доступ.**

## Главное ограничение остаётся

Стабильного ID вакансии нет — только `(channel, message_id)`. Следствия:

- репост той же вакансии = новая запись
- закрытие вакансии никак не отражается, пост просто висит
- времени жизни вакансии телеграм не даст — главную метрику проекта отсюда
  не посчитать
- дедупликация только вероятностная, а компанию указывают не всегда

Исключение — @findwork с его `devkg.com/tg/j-NNNNN`.
