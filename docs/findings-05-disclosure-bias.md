## Два разных смещения

**Между профессиями — измеримо и поправимо.** Состав выборки не совпадает
с составом рынка. Исправляется взвешиванием: медиана по каждой профессии
считается на её выборке, а общая — взвешивается по **реальной** доле
профессии, а не по доле в выборке.

**Внутри профессии — неизмеримо.** Платят ли раскрывающие работодатели
больше или меньше молчащих — данных нет ни у кого. Скрытых вилок не видит
никто, включая саму площадку.

Второе смещение не устраняется. Его можно только назвать в методологии.

---

## Что делать

### 1. Не публиковать «медиану по IT» как есть

Или публиковать с явной поправкой: взвешивать профессии по их доле
на рынке, а не по доле в зарплатной выборке.

### 2. Показывать процент раскрытия рядом с каждой цифрой

```
Дата-сайентист, Алматы: 1 000 000 ₸   (11 из 58 вакансий, 19% раскрытия)
```

Читатель сам поймёт, насколько цифре доверять. Это честнее любой поправки
и ничего не стоит.

### 3. Формулировать метрику точно

Не «медиана зарплат IT-специалистов», а **«медиана по вакансиям
с указанной вилкой»**. Разница принципиальная, и именно на ней ловят
зарплатные обзоры.

### 4. Разрезы по профессиям остаются честными

Внутри одной профессии смещение одинаковое для всех наблюдений.
Сравнивать «дизайнер против программиста» можно, а складывать их
в одну медиану — нет.

---

## Почему это нашлось только сейчас

Первая попытка запроса дала **100% раскрытия у всех двадцати профессий** —
и цифра выглядела правдоподобно. Ошибка была в `payload -> 'salary'
is not null`: для `"salary": null` это истинно, потому что jsonb 'null'
не является SQL NULL (см. `docs/data_notes.md` §9).

То есть находку чуть не похоронил тихий баг, который не падает,
а выдаёт красивое неверное число.

**Урок:** любую подозрительно ровную цифру проверять независимым способом.
100% у двадцати разных профессий не бывает.
