# dbt

## Зачем

Версионирование логики трансформаций, тесты качества и lineage.
Центральный обучающий элемент проекта (ТЗ §4.2).

## Что здесь есть

**Staging** — механическая распаковка jsonb, никакой бизнес-логики:

| Модель | Что делает |
|---|---|
| `stg_hh_vacancies` | вакансии hh: типы, оба поля зарплаты, RUR→RUB, вырезание контактов |
| `stg_market_counters` | счётчики рынка по странам |
| `stg_currency_rates` | курсы к USD |
| `stg_telegram_posts` | посты каналов; разбор текста — в `enrichment/`, там тесты |

**Marts** — `mart_market_share`: доля IT в рынке труда по дням, изменение
ко вчера, скользящее среднее за 7 дней и флаг аномалии объёма (ТЗ §8.1).

**Seeds** — `profession_map` (25 IT-ролей hh) и `skill_categories` (80 навыков).

## Что пишется вручную

**Весь core** и витрины поверх него. Это целевые компетенции
проекта (ТЗ §12.1): SCD2, оконные функции для времени присутствия в выдаче,
дедупликация. Готовая модель без понимания — тот же вайбкодинг, только через dbt.

Порядок из ТЗ §9, Фаза 2:

1. `fct_vacancy_snapshot` + время присутствия + детекция закрытий
2. SCD2 — сначала руками на малом наборе, сломать, потом `dbt snapshot`
3. Справочник профессий правилами, замерить долю нераспознанных
4. Нормализация зарплат и курсы
5. `dim_company` — внутри hh хватает `employer_id`, нормализация имён
   нужна только между источниками (docs/data_notes.md §1)
6. Дедупликация, этап 1

## Запуск

```bash
cp dbt/profiles.yml.example ~/.dbt/profiles.yml   # подставить пароль
cd dbt && dbt deps && dbt run --select staging && dbt test --select staging
```
