# ingestion — сбор сырых данных

## Принцип

```
fetch  →  write_raw  →  validate  →  alert
```

Сырьё пишется в бакет **до** любой валидации. Валидация — сигнал нам, а не шлагбаум
для данных: упавшая проверка схемы не должна стоить дня истории.

## Установка

```bash
python3 -m venv .venv && .venv/bin/pip install -e .
cp .env.example .env   # заполнить
```

## Запуск

```bash
.venv/bin/python -m ingestion.run                  # все страны, сегодня
.venv/bin/python -m ingestion.run --country kz     # одна страна
.venv/bin/python -m ingestion.run --dt 2026-09-03  # бэкфилл партиции
.venv/bin/python -m ingestion.run --skip-details   # только списки, быстро
```

## Cron

```cron
0 3 * * * cd /path/to/talap && .venv/bin/python -m ingestion.run >> /var/log/talap.log 2>&1
```

Airflow ставится позже. Cron выключается только после трёх суток стабильной работы Airflow.

## Структура ключей в бакете

```
raw/hh/country=kz/dt=2026-09-04/vacancies_list-000.json.gz
raw/hh/country=kz/dt=2026-09-04/vacancy_details-000.json.gz
```

## Что делает код

| Модуль | Ответственность |
|---|---|
| `config.py` | Конфигурация из окружения, ничего не хардкодится |
| `http.py` | Экспоненциальный backoff на 429 и 5xx, учёт `Retry-After`, троттлинг |
| `storage/s3.py` | gzip-JSON в S3-совместимый бакет, очистка партиции |
| `sources/hh.py` | Клиент hh: справочники, адаптивная нарезка, детали |
| `schemas/hh.py` | Сигнальная валидация (`extra="allow"`), никогда не бросает |
| `alerts.py` | Telegram-уведомления |
| `run.py` | Оркестрация одного запуска |

## Ключевые решения

**Адаптивная нарезка.** Глубина выдачи ограничена, всю выдачу одним запросом не забрать.
Режем по `area × professional_role`; если срез не влезает — рекурсивно делим окно дат
публикации пополам (`_split_by_date`). Срезы, которые не удалось разделить, попадают
в алерт, а не молча теряются.

**Детали только по дельте.** Список не содержит полного описания, детали — запрос
на вакансию. Грузим только ID, которых не было вчера. Предохранитель
`MAX_DETAILS_PER_RUN`: аномально большая дельта означает битую вчерашнюю партицию.

**Справочники из API.** Коды `area` и `professional_role` не хардкодятся — резолвятся
на каждом запуске. Справочники живые.

**Идемпотентность.** Повторный запуск за дату удаляет партицию и пишет заново.

**Изоляция отказов.** Падение одной страны не блокирует остальные.

## Ограничения текущей версии

- `DEPTH_LIMIT = 2000` взят из документации, **не подтверждён замером**
- Нет `meta.ingestion_log` — пишем в лог, таблица появится с Postgres
- Нет проверки объёма ±40% от скользящего среднего
- Детали грузятся только для новых ID; изменения в существующих вакансиях
  подхватываются из списка, но не из полного описания
